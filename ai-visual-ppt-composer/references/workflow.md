# AI Visual PPT Composer Workflow Reference

## 1. Why this workflow exists

Traditional AI PPT generation often fails in one of three ways:

1. **AI-generated full-page image**: visually rich but text is wrong and nothing is editable.
2. **Direct PPT generation**: editable but visually plain, rigid, and template-like.
3. **Image-to-PPT reconstruction**: often produces poor element detection, broken alignment, wrong icons, and inaccurate text.

This workflow avoids those failure modes by splitting responsibilities:

- Image model: background, atmosphere, lighting, texture, decorative visual complexity.
- Code: layout, exact text, data, diagrams, typography, alignment.
- PPTX library: native PowerPoint elements.

## 2. Recommended production pipeline

```text
User outline / source PPT / reference visual
        ↓
Content understanding and slide plan
        ↓
Visual style contract
        ↓
Per-slide no-text background prompts
        ↓
AI-generated backgrounds or user-provided background assets
        ↓
deck.json with exact element coordinates
        ↓
HTML/CSS/SVG preview render
        ↓
PPTXGenJS native reconstruction
        ↓
Quality check and refinement
        ↓
Final PPTX + PNG/HTML previews
```

## 3. Layer definitions

### Background layer

Can be a raster image generated by Image 2, GPT image, Midjourney, Flux, Stable Diffusion, or a user-provided visual.

Allowed:

- gradients
- light effects
- abstract shapes
- background photos
- atmospheric illustrations
- decorative wireframes without readable text
- empty cards or panels without labels

Forbidden unless explicitly requested:

- readable text
- fake letters
- fake numbers
- pseudo charts with labels
- fake UI glyphs
- logos
- watermark
- QR code
- fake data

### Content layer

Must be editable:

- title
- subtitle
- body text
- data labels
- chart labels
- footnotes
- page numbers
- section markers
- tables
- diagrams

### Decorative layer

Usually editable or vector:

- rounded cards
- translucent glass panels
- divider lines
- glows
- chips/badges
- arrows
- dots
- diagrams

## 4. Visual style contract

Before building, create a compact style contract:

```json
{
  "deck_type": "roadshow / academic / policy / tutorial / product",
  "mood": "premium, cinematic, precise",
  "palette": ["#..."],
  "background_style": "no-text AI generated abstract atmosphere",
  "typography": {
    "title": "heavy sans, high contrast",
    "body": "clear sans, high readability"
  },
  "layout_rules": [
    "one visual center per slide",
    "large title with strong contrast",
    "body content organized into 2-4 blocks"
  ],
  "editability_rules": [
    "all readable text must be native PPT text",
    "diagrams should be native shapes where practical",
    "background can remain raster"
  ]
}
```

## 5. Slide planning template

For each slide, produce:

```text
Slide N — title
Purpose: what the slide communicates.
Layout: hero / split / cards / timeline / comparison / diagram / closing.
Background: what visual atmosphere the image model should generate.
Editable elements: title, body, cards, labels, chart, page number.
Risk: what can go wrong visually.
Fix: how to avoid the risk.
```

## 6. Common page patterns

### Cover

- Large title, usually left aligned or center aligned.
- No more than 2-3 text groups.
- Background has strong atmosphere but must leave clean title zone.

### Section divider

- One big chapter title.
- Minimal supporting text.
- Strong visual metaphor.

### Three-card argument slide

- Title top-left.
- Three cards across or staggered.
- Each card: icon/number, heading, 2-3 body lines.
- Background should be quieter than cards.

### Timeline

- Native line/shape elements.
- AI background only provides depth and ambience.
- Dates and labels must be editable.

### Roadshow business model

- Use a central mechanism diagram.
- Use arrows and rounded boxes as native shapes.
- Use no fake diagrams inside the background.

### Academic literature slide

- Keep visuals restrained.
- Use structured blocks, highlight boxes, chart placeholders.
- Avoid overly decorative title effects.

## 7. Acceptance criteria

A slide is acceptable only if:

- text is correct and editable;
- layout is readable at 100% zoom;
- title hierarchy is obvious within 2 seconds;
- background has no gibberish or fake text;
- no element is visibly misaligned;
- the deck has consistent style but each page has its own composition.
