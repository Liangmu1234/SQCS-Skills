# 项目会议纪要生成

将会议转写整理成项目会议纪要 Excel，并安全归档到项目的 `8.其他` 目录。始终复制模板后再填写，绝不修改模板原件。

## 固定路径

- 会议纪要模板和项目目录模板仓库：`https://github.com/Liangmu1234/Meeting-Minutes-Template`（`main` 分支）
- 本地受控缓存：`%LOCALAPPDATA%\Codex\Meeting-Minutes-Template`（远端历史重写时使用带提交号后缀的只读快照）
- 项目信息根目录：`D:\文档\00-项目信息`
- 最终归档子目录：`8.其他`

## 工作流

### 1. 读取并整理转写

1. 完整读取用户提供的全部转写文件。
2. 如果中文乱码，先检查字节编码并恢复，不能直接依据乱码写纪要。
3. 从转写和用户上下文提取：
   - 项目名称、客户名称、会议日期和地点；
   - 参会人及角色；
   - 项目背景、测试性质、范围和目标；
   - 测试方式、时间、地点、设备、软件、网络和交付件；
   - 结论、负责人、完成时间；
   - 风险、遗留问题及规避措施。
4. 清理寒暄、重复、语气词和明显识别错误。产品名、型号、数字和人名不确定时标为“待确认”，不得猜测。
5. 客户名称、项目名称与群名、文件名不一致时，以会议中的明确更正和客户沟通结论为准；无法确认时标为“待确认”，不得沿用错误简称。

### 2. 确定项目和会议日期

- 优先使用用户明确给出的项目名和日期，其次使用转写中的明确信息。
- 不要把客户简称自动当成完整项目名；用现有目录名称辅助匹配。
- 如果多个项目目录都可能匹配，停止写入并向用户确认。
- 如果项目不存在但项目名或会议日期不明确，先询问用户；目录创建属于不可随意猜测的操作。
- 会议日期决定新项目的年度、季度和文件名。季度规则：1—3月为Q1，4—6月为Q2，7—9月为Q3，10—12月为Q4。

### 3. 选择会议纪要模板

1. 用户提供模板时，使用该模板，但仍先复制到目标项目目录，再编辑副本。
2. 用户未提供模板时，读取 [references/template-selection.md](references/template-selection.md)，从 GitHub 模板仓库刷新本地受控缓存，并检查仓库根目录中的实际文件。
3. 根据会议主题和被测产品选择最匹配模板；选择不明确时向用户确认，不要随意套用。
4. 模板源文件和项目目录模板只读使用。记录复制前后的模板哈希，确认缓存源文件未变化；不得向 GitHub 仓库推送或写回模板。

### 4. 定位或创建项目目录

先搜索 `D:\文档\00-项目信息\<年份>\Q<季度>\` 及其他年份季度目录：

- 排除名称含 `项目模板` 的目录。
- 只有一个高置信匹配时，直接使用其 `8.其他`。
- 没有匹配时，从 GitHub 模板仓库中的 `00-[项目模板-XX年XX月]` 完整复制到会议日期对应的年度/季度目录，再重命名为：

```text
NN-[项目名称-YY年M月]
```

`NN` 取该季度现有项目两位数字序号的下一个可用值。复制后确认 `1.借货设备` 至 `8.其他` 目录完整存在；缺失时停止流程，不得创建不完整项目目录。

优先运行 [scripts/prepare_project_minutes.ps1](scripts/prepare_project_minutes.ps1) 完成 GitHub 模板同步、项目查找、项目模板复制和会议模板副本创建。脚本遇到多项目匹配会报错，不能绕过后强行写入。本机限制 PowerShell 脚本执行时，使用：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "<skill>\scripts\prepare_project_minutes.ps1" -MinutesTemplateName "异构服务器.xlsx" ...
```

### 5. 填写 Excel 副本

模板为 `.xlsx`，必须同时使用 `spreadsheets:Spreadsheets` 技能：

1. 调用工作区依赖加载器并使用 `@oai/artifact-tool`。
2. 编辑前导入并渲染副本，检查页签、合并单元格、现有值、数据验证、行高列宽和样式；必要时对照模板源文件读取验证类型、允许值和数值范围。
3. 只把事实填入相应字段，保留模板布局、公式、下拉验证和备注说明。不得改写字段标题、预置部门/角色、固定备注/说明、密级等固有字段。
4. “与会者”区域仅填写空白的姓名输入位；保留原有的“与会者部门”“与会者角色”“备注”及其预置内容。不根据发言内容擅自替换部门或角色字段。
5. 至少填写适用的以下板块：
   - 会议时间、地点、参会人、召集人和纪要整理人；
   - 项目基本信息；
   - 项目需求信息；
   - 项目组成员和职责；
   - 风险级别、风险描述、规避手段和影响；
   - 会议遗留问题、要求、完成时间和责任人。
6. 对尚未闭环的事项，在“是否遗留问题”列标记“是”，并在遗留问题表中逐项列出。
7. 用户没有提供、转写也未明确的信息写“待确认”或留空；不得虚构预算、投标时间、客户关系、功能满足度或人员角色。
8. 对带下拉、数值、日期或其他数据验证的单元格，只能写入模板允许的值。无法从转写确认时必须留空，不得填写“待确认”或其他自由文本；数值/日期受控字段也不得用文本占位。
9. 导入、导出或写入可能丢失数据验证时，按源模板的验证类型、`Formula1`、`Formula2`、允许空白和下拉选项恢复规则，再导出最终文件。
10. 最终文件默认命名：

```text
YYYY-MM-DD-项目名称-会议纪要-模板名称.xlsx
```

文件必须保存在目标项目的 `8.其他` 目录。

### 6. 校验和交付

完成前必须：

1. 检查最终文件存在且为有效 XLSX。
2. 复核项目路径、会议日期、项目名称和模板类型。
3. 检查关键单元格的值及公式错误。
4. 逐项检查所有受数据验证控制的单元格：验证规则与源模板一致，已填值属于允许范围，无法确认的下拉/数值/日期项为空。
5. 复核固定字段未被改写，尤其是与会者部门、角色、备注、模板说明和预置标签。
6. 渲染所有页签，修复内容遮挡、合并单元格写入错误、文字截断和明显格式异常。
7. 比较模板源文件复制前后的哈希，确认原件未被修改。
8. 向用户报告新建或复用的项目目录，并提供最终会议纪要文件链接。

## 安全规则

- 不覆盖会议纪要模板原件或项目文件夹模板。
- 默认从 GitHub 模板仓库的 `main` 分支刷新受控缓存；不得修改缓存源文件、修改远端仓库或以本地旧模板替代默认远程来源。远端历史重写时保留原缓存并创建新的提交快照，不得强制重置已有缓存。
- 目标文件已存在时默认生成带序号的新文件；只有用户明确要求才覆盖。
- 不因模糊简称、同名客户或相似项目自动选择目录。
- 不移动、删除或重命名现有项目目录。
- 新建项目时只能复制 GitHub 中的完整标准项目模板；缺失任何标准子目录时停止，不得手工创建或猜测项目目录。
- 不修改模板中已有的字段名、预置选项、部门/角色行、固定备注、数据验证或公式；只向允许的输入位写入事实内容。
